# Хранилище `.xplain/`

Все данные XPlain лежат в проекте, в папке `.xplain/` в корне первого workspace-фолдера. Папка создаётся
автоматически при активации расширения. Формат — обычные JSON- и текстовые файлы, пригодные для чтения,
правки и коммита в git.

```
.xplain/
  .gitignore                      # *.tmp
  index.json                      # якоря + метаданные сессий
  sessions/
    <sessionId>/
      context.json                # что было отправлено, заголовок, статус, ошибка
      result.html                 # ответ агента (self-contained HTML; старые result.md ещё читаются)
  templates/
    <templateId>/
      template.json               # имя, инструкция, список файлов
      files/<имя файла>           # приложенные файлы
  ui/
    background.<ext>              # фон панели для проекта (опционально)
```

## `index.json`

```jsonc
{
  "version": 1,
  "anchors": [
    {
      "id": "mv2ngpzs-3f1a9c2b",
      "file": "debug_samples/4_warp_specialization.cu",   // относительный POSIX-путь
      "startLine": 192, "endLine": 221,                    // 1-based, включительно; обновляются при правках
      "textHash": "6f2c…",                                 // sha1 нормализованного текста блока
      "snippet": "for (int kv_tile = 0; …",                // текст блока для повторного поиска
      "language": "cuda"
    }
  ],
  "sessions": [
    {
      "id": "mv2ngpzs-a1e0626c",
      "title": "Barrier phases in the KV loop",
      "createdAt": "2026-10-10T17:05:12.345Z",
      "anchorIds": ["mv2ngpzs-3f1a9c2b"],                   // все блоки этого контекста
      "question": "Why does the MMA warp wait here?",
      "resultFormat": "html",                              // всегда "html" для новых сессий; "markdown" — legacy
      "status": "done",                                    // "pending" | "done" | "error"
      "error": "…"                                         // только при status = error
    }
  ]
}
```

### Якоря (anchors)

Якорь — блок кода, к которому привязаны объяснения. Связь «блок ↔ сессии» выражается через
`sessions[].anchorIds`: один якорь может входить в много сессий (несколько объяснений одного блока),
одна сессия — ссылаться на много якорей (общий результат для нескольких блоков).

Правила сопоставления при добавлении выделения (`upsertAnchor`):

1. тот же файл, тот же диапазон, тот же `textHash` → существующий якорь;
2. тот же файл и `textHash`, но другой диапазон → блок переместился: якорь переиспользуется, диапазон обновляется;
3. иначе → новый якорь. Подблок внутри существующего блока — всегда отдельный якорь.

Нормализация текста перед хешированием: `\r\n → \n`, обрезка пробелов в конце строк, обрезка пустых
строк в начале и конце. Так якорь устойчив к изменению окончаний строк и trailing whitespace.

Отслеживание во время редактирования:

- при каждом изменении открытого документа диапазоны сдвигаются (вставка/удаление строк выше блока,
  рост/сокращение внутри блока);
- если текст в диапазоне больше не совпадает с хешем, блок ищется по `snippet` по всему файлу
  (ближайшее к прежней позиции вхождение);
- если не найден, но диапазон цел — блок считается *изменяемым* и продолжает отображаться; при
  сохранении файла якорь принимает новый текст (`snippet`, `textHash` обновляются);
- если блок удалён — якорь становится *stale*: CodeLens скрыт, запись сохраняется (вернётся, если
  текст появится снова, например после undo или `git checkout`).

Обновлённые диапазоны пишутся в `index.json` через ~1.5 с после правки и при сохранении файла.

Якоря, на которые не ссылается ни одна сессия, удаляются при удалении сессии.

## `sessions/<id>/context.json`

```jsonc
{
  "id": "mv2ngpzs-a1e0626c",
  "title": "Barrier phases in the KV loop",
  "createdAt": "2026-10-10T17:05:12.345Z",
  "question": "Why does the MMA warp wait here?",
  "items": [
    { "kind": "code", "anchorId": "…", "file": "…", "startLine": 192, "endLine": 221, "language": "cuda", "text": "…" },
    { "kind": "result", "sessionId": "…", "title": "Pipeline overview" },
    { "kind": "template", "templateId": "…", "name": "CUDA kernel review" }
  ],
  "agent": { "provider": "hermes", "endpoint": "http://127.0.0.1:8642/v1", "model": "hermes-agent" },
  "status": "done"
}
```

`text` блоков фиксируется на момент отправки — это «снимок» того, что видел агент, даже если код потом
изменился. Содержимое результатов и файлов шаблона в `context.json` не дублируется (есть ссылки).
`agent` описывает, кто ответил: `provider` (`xplain` | `hermes` | `openai` | `anthropic` | `mock`;
в сессиях версии 0.1 — `http`), `endpoint` (endpoint или base URL) и `model` (для чат-провайдеров).
Ключи API в хранилище не попадают.

## `sessions/<id>/result.html`

Ответ агента — один self-contained HTML-документ (`<!DOCTYPE html>`, inline CSS, без внешних скриптов).
Провайдеры просят модель отдавать HTML; если пришёл Markdown или HTML-фрагмент, XPlain оборачивает его
в полноценную страницу (`src/agent/htmlResult.ts`). Старые сессии с `result.md` по-прежнему открываются;
при повторном завершении сессии файл другого формата удаляется.

## `templates/<id>/`

```jsonc
// template.json
{
  "id": "mv2nh0ab-77c01d2e",
  "name": "CUDA kernel review",
  "instruction": "Explain memory access patterns…",
  "files": [ { "name": "notes.md", "size": 1834 } ],
  "createdAt": "…", "updatedAt": "…"
}
```

Файлы хранятся в `files/` под очищенными именами (путь отбрасывается, запрещённые символы заменяются
на `_`, коллизии получают префикс `_`). При сохранении шаблона папка `files/` перезаписывается целиком.
Шаблоны можно создавать и руками: достаточно папки с корректным `template.json`, где `id` равен имени папки.

## `ui/background.<ext>`

Фон панели «для этого проекта». Пользовательский фон («для меня») хранится вне проекта —
в global storage расширения (`context.globalStorageUri`), имя файла запоминается в `globalState`.

## Идентификаторы

`<base36 времени>-<8 hex случайных>` — короткие, безопасные для файловой системы, сортируются по времени создания.

## Внешние изменения и git

- Расширение следит за `index.json` и `templates/**` (FileSystemWatcher) и перечитывает данные при
  изменениях извне (git pull, ручная правка, второе окно). Собственные записи игнорируются ~1.5 с.
- Запись атомарная: сначала `*.tmp`, затем `rename`. `.xplain/.gitignore` исключает `*.tmp`.
- `.xplain/` можно коммитить, чтобы делиться объяснениями с командой. В корневом `.gitignore` репозитория
  XPlain эта папка исключена только потому, что сам репозиторий — исходники расширения.
- Чтобы начать с чистого листа — удалите `.xplain/` и перезагрузите окно.
