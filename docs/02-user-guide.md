# Руководство пользователя

## Панель XPlain

Клик по иконке XPlain в activity bar открывает панель на всю ширину sidebar. В ней пять вкладок:

| Вкладка | Назначение |
| --- | --- |
| **Context** | Текущий контекст: блоки кода, ранее полученные результаты, шаблон, вопрос, кнопка отправки |
| **Result** | Открытое объяснение (Markdown или HTML); во время запроса — потоковый вывод |
| **Templates** | Создание и редактирование шаблонов (инструкция + файлы) |
| **History** | Все сессии проекта с фильтром; открыть, добавить в контекст, удалить |
| **Agent** | Выбор провайдера (Hermes / Claude / OpenAI-Codex / Cursor SDK), адреса, модель, ключ API, проверка соединения |

Числовые бейджи на вкладках показывают количество элементов контекста и готовых результатов.

## 0. Настроить агента (один раз)

Перед первой отправкой откройте вкладку **Agent** (или кликните имя агента внизу вкладки Context,
или команду **XPlain: Configure Agent**). Подробно — в разделе [Вкладка Agent](#вкладка-agent).

## 1. Добавить код в контекст

1. Выделите блок кода мышью или клавиатурой.
2. Нажмите **Shift+X**.

Выделение расширяется до целых строк; в контексте появляется элемент вида
`4_warp_specialization.cu L192-L221`. Панель открывается автоматически (фокус остаётся в редакторе),
в статус-баре мелькает подтверждение, блок подсвечивается в редакторе.

При отправке агенту вместе с каждым блоком уходит **весь файл** как окружающий контекст, но в
инструкции явно сказано объяснять **только** выбранный диапазон строк, а не файл целиком.

Дополнительно:

- Можно выделить несколько фрагментов (multi-cursor) — каждый станет отдельным элементом.
- Повторное добавление того же блока не создаёт дубликата.
- Контекстное меню редактора → **XPlain: Add Selection to Context** — то же действие мышью.
- Шаблон внутри блока: если выделить несколько строк внутри большого блока, это **отдельный** якорь
  со своими результатами. Таким образом строки/подблоки внутри блока могут иметь собственные объяснения.

В списке контекста у элемента есть действия: перейти к коду (клик по названию), переместить выше,
удалить. Кнопка «очистить» в заголовке секции (или `XPlain: Clear Context`) очищает всё.

## 2. Вопрос, шаблон и опции

- **Your question** — свободный текст; необязателен. Ctrl+Enter в этом поле отправляет запрос.
- **Template** — выпадающий список сохранённых шаблонов. Выбранный шаблон добавит в запрос свою
  инструкцию и файлы. Иконка «карандаш» открывает шаблон для редактирования.
- **Explanation language** — язык ответа агента: *English* или *Russian*. Идентификаторы кода, пути
  файлов и ссылки на строки (`L12-L48`) остаются без перевода.
- **Draw diagrams with the Excalidraw skill** — чекбокс. Когда отмечен, перед отправкой XPlain кладёт
  скилл [excalidraw-diagram-skill](https://github.com/coleam00/excalidraw-diagram-skill) в
  **`.xplain/skills/excalidraw-diagram/`** (агент-агностичное хранилище) и в runtime адаптирует его под
  выбранного агента: для Cursor — bridge в `.cursor/skills/` + `settingSources: project`, для Hermes/Anthropic —
  bridge в `.claude/skills/`, для остальных — путь к store в промпте. Агент рендерит PNG в
  `.xplain/diagrams/<sessionId>/` (без переиспользования чужих картинок) и ссылается путями;
  XPlain сам встраивает файлы в `result.html` (агент не должен стримить base64).

Шаблон, язык и чекбокс диаграмм сохраняются между отправками, Clear context и перезагрузками окна
(workspaceState). Текст вопроса после отправки/очистки не сохраняется.

Контекст может состоять только из вопроса (без кода) — например, общий вопрос по проекту.

## 3. Отправка агенту

Кнопка **Send to agent** активна, когда в контексте есть хотя бы один элемент или введён вопрос.
Ничего не отправляется до нажатия. Внизу слева показан текущий провайдер и модель/endpoint
(клик открывает вкладку **Agent**). Перед отправкой XPlain собирает **один** `systemPrompt` и блок
`instructions` (язык, формат HTML, пути к картинкам, Excalidraw) — одинаковый для Hermes, OpenAI,
Anthropic, Cursor SDK и XPlain HTTP.

После нажатия:

1. Создаётся сессия в `.xplain/sessions/<id>/` с предварительным заголовком.
2. Панель переключается на **Result**; если агент стримит, текст появляется по мере генерации.
3. По завершении результат сохраняется, заголовок обновляется, контекст очищается.
4. Над каждым блоком, участвовавшим в контексте, появляется CodeLens.

Пока агент работает, вверху панели виден баннер с кнопкой **Stop** (также в футере Context,
в Result во время стрима, иконка в заголовке панели и команда **XPlain: Stop Agent Request**;
в статус-баре окна IDE — Cancel у прогресса). Остановка abort'ит HTTP-запрос и прерывает работу
агента; незавершённая сессия удаляется. При ошибке сессия помечается `failed` (видна в History),
контекст сохраняется, чтобы повторить отправку.

## 4. Результаты в редакторе

Над блоком с объяснениями отображается CodeLens:

- `XPlain: <заголовок>` — одно объяснение;
- `XPlain: 3 explanations · <последний заголовок>` — несколько.

Клик по CodeLens открывает выпадающий список (Quick Pick) всех объяснений этого блока:
заголовок, давность, вопрос. Enter — открыть в панели. У каждого пункта кнопки:
**Download** (Save As для `result.html` / `result.md` — работает сразу, не ждёт рендер),
**Open in editor** (предпросмотр Markdown / отдельная вкладка для HTML) и **Add to context**.
Последний пункт списка — «Add this code block to context» (добавить сам блок мышью, без Shift+X).

Также блок помечен иконкой в gutter и подсветкой; при наведении — список объяснений со ссылками.

Правила привязки:

- Один блок несколько раз в разных контекстах → несколько пунктов в списке.
- Один контекст с несколькими блоками → у каждого блока один и тот же результат (общий заголовок).
- Отдельные строки/подблоки внутри блока → собственные CodeLens и списки.
- Заголовки — осмысленные (как названия чатов): их задаёт агент; если нет — первый заголовок ответа,
  вопрос или имя файла с диапазоном. Заголовок можно переименовать: двойной клик по нему на вкладке Result.

Якоря следуют за правками файла: при вставке/удалении строк диапазон сдвигается, при редактировании
внутри блока объяснения остаются, при повторном открытии файла блок переищется по содержимому.

## 5. Extend — правка существующего результата

Откройте объяснение (CodeLens → Result). Нажмите **Extend**:

1. Контекст заполняется базовым результатом и его исходными блоками кода.
2. Напишите follow-up вопрос, при необходимости перетащите текстовые файлы во вкладку Context,
   добавьте ещё блоки через Shift+X / pick mode, либо явно добавьте другие результаты.
3. **Send (overwrite)** перезаписывает тот же `sessions/<id>/result.html` (новый CodeLens не создаётся).
   При ошибке или Stop прежний результат на диске сохраняется.

Агент **не** должен подглядывать в другие сессии или чужие диаграммы, пока вы сами не добавили их в контекст
(см. изоляцию артефактов ниже).

## 5a. Код изменился после объяснения (drift)

XPlain помнит хеш кода, который видел агент, для каждого блока сессии и сравнивает его с текущим
текстом файла (открытого или на диске). Объяснения **никогда не удаляются и не перегенерируются
автоматически** — вместо этого показывается степень расхождения:

| Состояние | Что значит | Где видно |
| --- | --- | --- |
| *fresh* | Код совпадает. Правки только в комментариях/пробелах тоже считаются fresh | обычный CodeLens |
| *code changed* | Небольшая правка внутри блока (до `xplain.drift.driftedMaxLines` строк или ≤ `outdatedRatio`) | CodeLens `· $(edit) code changed`, синий чип в History/Result |
| *outdated* | Изменилась первая значимая строка блока (сигнатура) или большая доля строк | CodeLens `· $(warning) outdated`, жёлтый чип, пунктирная рамка |
| *lost* | Блок не найден в файле (удалён / переписан) | чип «code not found» в History |

Действия:

- **Show diff** (hover блока, Quick Pick, баннер на Result, History) — открывает VS Code diff
  «explained ↔ current» для каждого изменённого блока (виртуальные документы, файл не трогается).
- **Refresh** — один клик: контекст заполняется старым результатом, **текущим** кодом тех же блоков и
  файлом `code-changes.diff`, вопрос подставляется автоматически («обнови объяснение под текущий код,
  сохрани верное, исправь устаревшее, укажи изменения в поведении»; на русском при `xplain.explain.language = ru`),
  и запрос сразу отправляется. По умолчанию результат перезаписывает ту же сессию (как Extend);
  `xplain.refresh.mode = newSession` создаёт новое объяснение и оставляет старое в History.
- `xplain.editor.hideOutdated = true` прячет CodeLens для outdated/lost сессий (в History они остаются).

Пороги `xplain.drift.outdatedRatio` (0.3) и `xplain.drift.driftedMaxLines` (10) настраиваются.

## 6. Повторное использование результата (pick mode)

Чтобы подать уже имеющееся объяснение в **новый** контекст (не overwrite):

1. Уберите фокус из редактора (кликните в панель XPlain, Explorer и т.п.).
2. Нажмите **Shift+X** — включится *pick mode*: оранжевый индикатор в статус-баре и баннер в панели.
3. Кликните CodeLens нужного блока и выберите объяснение. Оно добавится в контекст; режим выключится.

Pick mode выключается повторным Shift+X, кликом по индикатору/баннеру, либо автоматически через 2 минуты.

Альтернативы без режима: кнопка «+» в hover блока, в Quick Pick, в History и на вкладке Result.
На вкладке Context можно перетаскивать текстовые файлы как вложения (до 1 МБ).

## 7. Просмотр результатов

- **Markdown** рендерится в панели с подсветкой кода. Ссылки открываются во внешнем браузере.
- **HTML** (self-contained) показывается в Shadow DOM панели Result; встроенные `data:`-картинки видны,
  доступа к API VS Code у разметки нет. Большие HTML с диаграммами могут несколько секунд показывать
  «Rendering…» — **Download** сохраняет файл с диска без ожидания. «Open in editor» — отдельная вкладка.
- История: вкладка **History** — фильтр по заголовку/вопросу, открытие, добавление в контекст, удаление
  (с подтверждением; удаляются файлы сессии, «осиротевшие» якоря убираются).

## 8. Изоляция артефактов

В запрос попадают **только** элементы черновика (код, явно добавленные результаты, файлы, шаблон).
Агенту запрещено читать `.xplain/sessions/**` и чужие `.xplain/diagrams/<id>/`; разрешены скиллы и
`.xplain/diagrams/<текущаяСессия>/`. Диаграммы — пути в HTML, без стриминга base64; XPlain сам
встраивает PNG при сохранении.

Для **Cursor SDK** дополнительно: управляемый блок в `.cursorignore` (маркеры
`xplain-agent-isolation`), чтобы ignored-пути были недоступны инструментам. Для Hermes/chat —
контракт в промпте (чат без FS уже изолирован).

## 9. Шаблоны

Шаблон = имя + инструкция для агента + набор текстовых файлов (документация, заметки, примеры).

Три уровня хранения:

| Уровень | Где лежит | Кто правит |
| --- | --- | --- |
| **Built-in** | `bundled-templates/` внутри расширения | только чтение; **Duplicate** → user/project |
| **User** | global storage расширения | вы, во всех проектах |
| **Project** | `.xplain/templates/<id>/` | вы, в этом workspace (можно коммитить) |

Создание (вкладка **Templates**):

1. Введите имя и инструкцию.
2. Выберите **Save to**: Project или User.
3. Добавьте файлы: drag-and-drop или «browse…» (текст до 1 МБ).
4. **Save template**. Шаблон появляется в списке и в выпадающем списке на вкладке Context.

В списке: клик по имени — выбрать/снять для контекста; у user/project — редактировать/удалить;
у built-in — копировать в user или project.

## Вкладка Agent

Здесь выбирается, кто будет отвечать на запросы, и вводятся все нужные данные — без правки `settings.json`.

### Провайдеры

| Провайдер | Когда выбирать | Поля |
| --- | --- | --- |
| **Hermes Agent** | У вас запущен Hermes harness с API-сервером | Base URL (`http://127.0.0.1:8642/v1` — именно API-сервер, **не** адрес Remote gateway из Hermes Desktop), модель/профиль — выбирается из списка, который отдаёт harness, ключ = `API_SERVER_KEY` из `~/.hermes/.env` |
| **Anthropic / Claude (Subscription)** | У вас подписка Claude Pro/Max, ключ API не нужен | Модель (пусто = по умолчанию у Claude Code); кнопки **Install claude CLI** / **Log in** / **Run doctor** / **Quota** — см. ниже |
| **Anthropic / Claude (API)** | Прямой доступ к Claude по API-ключу (оплата за токены) | Base URL (`https://api.anthropic.com`), модель (например `claude-sonnet-5`), `max_tokens`, ключ API (обязателен) |
| **OpenAI / Codex (Subscription)** | У вас подписка ChatGPT Plus/Pro, ключ API не нужен | Модель (пусто = по умолчанию у Codex CLI); кнопки **Install codex CLI** / **Log in** / **Run doctor** / **Quota** |
| **OpenAI / Codex (API)** | OpenAI-модели по API-ключу, или совместимый сервер (Ollama, vLLM, LiteLLM, OpenRouter) | Base URL (`https://api.openai.com/v1`), модель, ключ API (для локальных серверов не нужен) |
| **Cursor SDK** | Локальный Cursor-агент через `@cursor/sdk` в текущем workspace | Модель из аккаунта Cursor (напр. `composer-2.5`), API key с [Integrations](https://cursor.com/dashboard/integrations) |
| **XPlain HTTP agent** | Не в UI; только через `xplain.agent.provider = xplain` — свой сервис по [контракту](04-agent-api.md#контракт-xplain-provider--xplain) | Endpoint (`POST`), ключ — опционально |
| **Mock (offline)** | Не в UI; только `xplain.agent.provider = mock` для офлайн-проверки | — |

### Subscription-провайдеры (Claudexor)

Варианты **(Subscription)** работают через [Claudexor](https://github.com/razzant/claudexor) — CLI,
который поставляется **вместе с расширением** (`node_modules/claudexor` внутри VSIX) и управляет
официальными CLI вендоров: **Claude Code** (подписка Anthropic) и **Codex CLI** (подписка ChatGPT).
Маршрут выбирается автоматически (`xplain.agent.claudexor.mode = auto`):

- без Excalidraw — read-only `claudexor ask` в приватной папке расширения: агент ничего не пишет,
  к проекту доступа не получает (весь код уже в промпте);
- с галочкой Excalidraw — write-capable `claudexor agent --in-place --access workspace_write --no-review`,
  чтобы скилл мог отрендерить PNG. Где именно он работает, задаёт `xplain.agent.claudexor.project`:
  `auto` — в папке workspace, **только если это уже git-репозиторий** (Claudexor делает `git init` +
  baseline-коммит в не-git папках — этого XPlain с вашим проектом не делает); иначе — в приватной
  per-workspace папке в global storage расширения. Туда копируется скилл Excalidraw
  (`.xplain/skills/excalidraw-diagram`, для Claude Code ещё `.claude/skills/…`), а готовые
  `.xplain/diagrams/<sessionId>/` после запуска переносятся в ваш проект и инлайнятся в `result.html`
  как у остальных провайдеров. Первый рендер в приватной папке потребует разовой установки
  `uv sync && uv run playwright install chromium` — агент сделает это сам по инструкции скилла.

Требования: **Node.js ≥ 24.15** на машине, где работает расширение (при Remote-SSH — на сервере).
XPlain ищет его сам (ранее скачанный управляемый runtime, runtime extension host, `PATH`, nvm,
`/usr/local/bin`). Если ничего не подошло — при первом запросе скачивает официальную сборку с nodejs.org
(~55 МБ, проверка по `SHASUMS256.txt`) в `<globalStorage>/node-runtime/v<версия>/`; прогресс виден в строке
состояния и в Output. Скачать заранее можно кнопкой **Node.js runtime** во вкладке Agent (или
`XPlain: Set Up Subscription Harness…` → `node`). Отключается `xplain.agent.claudexor.autoInstallNode: false`;
свой бинарник — `xplain.agent.claudexor.nodePath`.

Первичная настройка (один раз, кнопки во вкладке Agent или команда
**XPlain: Set Up Subscription Harness…**) — всё выполняется в интегрированном терминале:

1. **Install claude/codex CLI** — `claudexor harness install <claude|codex> --target local --yes`
   ставит CLI вендора в управляемый toolchain `~/.claudexor/`. Если CLI уже установлен и виден в `PATH`
   (или задан `CLAUDEXOR_CLAUDE_BIN` / `CLAUDEXOR_CODEX_BIN`), шаг не нужен.
2. **Log in** — `claudexor auth login <claude|codex>`: стандартный логин вендора (браузер / device code).
3. **Test connection** — `claudexor doctor --harness …`: покажет `installed` / `auth` / доступные модели.
   **Quota** — текущие окна лимитов подписки.

Claudexor запускает фоновый демон `claudexord` при первом обращении; он остаётся работать между
запросами (остановить: `claudexor daemon stop`). Логи запросов — в Output → XPlain (`[claudexor] …`).

### Порядок действий

1. Выберите провайдера в выпадающем списке — ниже появятся его поля.
2. Заполните Base URL. Для Hermes / OpenAI / Anthropic XPlain **сам запрашивает у сервера список моделей**
   (`GET /models`) — при открытии вкладки, при смене провайдера или адреса и после сохранения ключа — и
   показывает его в выпадающем списке **Model**. Для Hermes это профили harness'а (`hermes-agent` и
   остальные). Кнопка ↻ перезагружает список, кнопка ✎ переключает на ручной ввод id (если нужной модели
   нет в списке). Если список получить не удалось (сервер не запущен, нет ключа), под полем выводится
   причина и остаётся обычное текстовое поле. Ранее сохранённая модель, которой нет в списке, остаётся
   выбранной с пометкой «not in the server list».
   Для всех провайдеров, кроме Hermes, под моделью есть поле **Reasoning effort** — уровень усилий
   рассуждения (пусто — значение модели по умолчанию). OpenAI (API) → `reasoning_effort`
   (`none…xhigh`), Anthropic (API) → `output_config.effort` (`low…max`), Subscription → `claudexor --effort`
   (Claudexor подрезает до уровней, которые объявляет модель), Cursor → параметр effort/thinking выбранной
   модели (список уровней приходит из аккаунта Cursor вместе с моделями; если у модели такого параметра нет,
   поле подписано и игнорируется). Кнопка ✎ позволяет ввести произвольный уровень, которого нет в списке.
3. **API key**: вставьте ключ и нажмите **Save key** (или Enter). Ключ сразу сохраняется в защищённое
   хранилище IDE (SecretStorage) отдельно для каждого провайдера; индикатор рядом с заголовком показывает
   `saved` / `not set` / `required`. **Clear** удаляет ключ. В поле ввода ключ никогда не отображается обратно.
   После сохранения ключа список моделей запрашивается заново.
4. **Test connection** — проверка соединения с текущими значениями формы (ключ берётся сохранённый):
   - Hermes / OpenAI / Anthropic / Cursor: запрашивается список моделей; выводится число моделей и есть ли среди
     них выбранная; выпадающий список обновляется.
   - XPlain HTTP agent: отправляется короткий ping-запрос; успешен любой валидный ответ.
5. **Save** — записать настройки. Переключатель **Save to** выбирает, куда:
   - *User settings* — для всех проектов (`settings.json` пользователя); при этом переопределения
     текущего workspace удаляются, чтобы они не перекрывали сохранённое;
   - *This workspace* — только для этого проекта (`.vscode/settings.json`).
   Значения, равные умолчанию, в файл не записываются (кроме `provider`). **Revert** отменяет несохранённые правки.

Пока есть несохранённые изменения, кнопка **Send to agent** использует *сохранённые* настройки — об этом
напоминает подпись под кнопками.

### Advanced

- **Idle timeout, minutes** — максимальная тишина без данных (по умолчанию **10** минут). Ждёт заголовки ответа, затем сбрасывается на каждом чанке тела (включая SSE keepalive и `hermes.tool.progress`).
- **Stream partial output** — показывать ответ по мере генерации (SSE для чат-провайдеров, NDJSON для XPlain).
- **System prompt** (не для XPlain-контракта) — заменить встроенную системную инструкцию. Пустое поле —
  встроенный промпт XPlain, который просит ответ в Markdown с коротким заголовком `#` первой строкой
  и ссылками на строки `L12-L48`.
- **Extra HTTP headers** — по одному на строку в виде `Name: value`; отправляются любому провайдеру.

Те же значения доступны как настройки `xplain.agent.*` (см. [Настройки](03-configuration.md)); вкладка —
просто удобный редактор для них. Если изменить настройки в `settings.json` вручную, форма обновится сама
(если в ней нет несохранённых правок).

## Горячие клавиши (сводка)

| Клавиши | Где | Действие |
| --- | --- | --- |
| Shift+X | редактор, есть выделение | добавить выделение в контекст |
| Shift+X | вне редактора (панель, Explorer, …) | включить/выключить pick mode |
| Ctrl+Enter | поле вопроса | отправить |
| Esc / Enter | переименование заголовка | отменить / сохранить |

Shift+X с выделением перекрывает ввод заглавной «X» поверх выделенного текста. Если это мешает,
переназначьте `xplain.addSelectionToContext` в Keyboard Shortcuts.
